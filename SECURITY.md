# Security policy

Postfader is a macOS-only beta intended for a trusted, single-user
workstation. It is not designed as a remote service, a multi-user control
plane, or a security boundary between mutually untrusted local processes.

## Supported versions

Security fixes are made on the default branch and included in the next tagged
release. Until a stable release line exists, only the latest public version is
supported.

The runtime compatibility gate requires FL Studio 2026 version 26.1.3 build
5336 or newer, MIDI scripting API 44 or newer, and a supported bridge protocol.
This is an interoperability gate, not a guarantee about FL Studio's own
security.

## Reporting a vulnerability

Use GitHub's **Security → Report a vulnerability** flow for this repository.
Do not publish exploit details, sensitive paths, project metadata, or audio in
a public issue.

Include:

- the affected revision or release;
- macOS, Python, and FL Studio versions;
- whether the bridge was read-only or write-enabled;
- the smallest synthetic reproduction you can provide; and
- the expected and observed security boundary.

If private vulnerability reporting is unavailable, open a public issue that
contains only a request for private contact. Do not include vulnerability
details until a private channel is established.

## Trust model

The intended deployment contains four components:

1. a trusted local MCP client;
2. the local stdio MCP server;
3. a shared local CoreMIDI/IAC bus; and
4. the FL Studio MIDI controller script.

The server and bridge implement no hosted service and no telemetry. Test
transports can use loopback or a local file mailbox; production FL Studio
communication on macOS uses MIDI SysEx over IAC.

The MCP client is outside this repository's trust boundary. It may send tool
arguments and results to a remote model provider. Those results can include
project title and author metadata, track and plug-in names, mixer state,
canonical audio paths, hashes, and measurements. Review the client's settings
and provider privacy policy before connecting a sensitive project.

## What an install carries

An installed copy contains program code and licence files, and no data. It
carries no record of the machine it was built on: no host validation record, no
build date, no captured session, and no measurements taken by anyone else. The
package hygiene tests assert this, so a data file cannot reappear unnoticed.

A capability report mixes three kinds of evidence and labels each one. Evidence
marked `live_read_only_test` comes from probing the FL Studio running now, and
says plainly when a probe did not succeed. Evidence marked
`official_documentation` or `local_static_inspection` is documentary — it
describes FL's published API or this bridge's own command allowlist, not your
machine. Read the `kind` field: nothing in a report asserts a runtime
observation that was not made on your host.

The three audio fixtures in the repository are generated by
`scripts/generate_audio_fixtures.py` and pinned by size and SHA-256. They are
synthetic signals, not recordings, and they are not installed by the package.

## MIDI transport

CoreMIDI/IAC is local but shared and unauthenticated. The connector's exclusive
lock prevents accidental duplicate ownership by cooperating client processes;
it does not authenticate the sender or protect against another local process
with MIDI access.

Every SysEx frame, assembled request or response, incomplete-message pool, and
bridge queue has a hard size or count ceiling. Fragments must use a consistent
non-zero total, an in-range sequence number, and contiguous parts; incomplete
messages expire after roughly ten seconds. The client accepts response fragments
only for its current serialized request ID, plus the small heartbeat on ID zero.
Malformed or excess traffic is discarded rather than retained indefinitely.

The MIDI transport is opt-in. It is constructed only when `FL_BRIDGE_ENABLE_MIDI=1`
is set for the process, so a process that has not asked for MIDI never opens
the shared bus. Every supported entry point sets it; omitting it is how a
caller says "this process must not touch the IAC bus."

A process that cannot open CoreMIDI at all — a CI runner, an automation
harness, anything without the entitlement — should set `FL_BRIDGE_SANDBOXED=1`.
The transport then reports itself unavailable rather than attempting a native
CoreMIDI client, which can abort the interpreter from C++ instead of raising.

Do not run the bridge on an untrusted shared Mac. Close other software that may
write to the selected IAC bus, and do not expose test transports beyond the
loopback interface.

## Write boundary

Read-only mode is the default. The ten supported write commands are added to
the bridge's active allowlist only when the FL Studio process starts with:

```bash
FL_BRIDGE_ENABLE_WRITES=1 open -a "FL Studio 2026"
```

Write tools apply immediately and do not perform a second confirmation
round-trip. Readback reports whether FL Studio appeared to move the target; it
does not provide rollback, audible validation, or a guaranteed undo point.
Mixer track 0 is refused unless explicitly authorized with `allow_master`.
The bridge never calls `saveProject`, but FL Studio or the user can later save
the changed project.

Use write mode only on a copy or disposable project until the workflow is
trusted. Do not invoke it while recording. Launch FL Studio normally to return
to read-only mode.

## Local file access

Direct audio-analysis tools accept caller-supplied absolute paths. They reject
relative paths, `..` components, directories, unsupported extensions, empty
files, and files larger than 512 MiB. A valid direct path can still identify an
audio file outside FL Studio's folders.

Measurement results expose the canonical path and SHA-256 hash to the MCP
client but do not include audio samples. Recent-bounce discovery is restricted
to fixed FL Studio output and project roots, does not follow directory
symlinks, and bounds scan depth and work.

Treat the connected MCP client as having read access to audio files that its
tool calls name. Do not connect an untrusted client or place sensitive audio
paths in prompts.

## Security invariants

The safe test suite checks important boundaries, including:

- strict MCP argument and result schemas;
- read-only and write-command allowlists;
- explicit Master targeting;
- no bridge call to `saveProject`;
- no automatic replay of ambiguous writes;
- bounded bridge work per FL Studio idle tick;
- MIDI framing and size limits;
- audio file type, size, and path checks;
- synthetic-only public fixtures; and
- no author host record in the installed package.

Run it with:

```bash
./.venv/bin/python scripts/run_safe_tests.py
```

Tests reduce risk but do not make a write reversible or make the shared IAC bus
authenticated.

## In scope

Examples of security issues worth reporting privately include:

- bypassing the read-only or Master-write gate;
- dispatching a bridge command outside the active allowlist;
- replaying a mutating command after an ambiguous response;
- escaping recent-bounce discovery roots;
- malformed MIDI input causing code execution or an unbounded resource use;
- sending project or audio information to an undeclared remote service; or
- packaging user projects, recordings, credentials, or private paths.

Issues in FL Studio, a third-party plug-in, an MCP client, or a model provider
should normally be reported to that product's maintainer unless this bridge
creates or materially worsens the vulnerability.
