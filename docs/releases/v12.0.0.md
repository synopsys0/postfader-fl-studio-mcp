# PostFader V12.0.0

V12 reorganizes PostFader's tools so that your AI client can tell them apart.
The server now exposes 85 tools instead of 135, every tool name follows one
pattern, and tools that did the same job in different ways are merged. FL
Studio behavior, safety checks, and saved runs and reviews are unchanged.

## What's new

- **One naming pattern.** Every tool is named `<area>_<verb>[_<object>]`,
  for example `mixer_set_track`, `plugin_list_presets`, or `run_execute`. The
  areas are `session`, `project`, `transport`, `mixer`, `channel`, `pattern`,
  `playlist`, `automation`, `plugin`, `atlas`, `processing`, `sound`, `audio`,
  `compose`, `piano_roll`, `run`, `review`, and `render`. The thirteen V11
  prefixes (`fl_`, `plugins_`, `mix_`, `postfader_`, `copilot_` and others)
  are gone.
- **One setter per target.** `mixer_set_track` replaces thirteen mixer setters:
  it sets any combination of volume (normalized or dB), pan, stereo
  separation, mute, solo, arm, name, color, built-in EQ bands, and sends on
  one mixer track, and can make it the active track. `channel_set`,
  `pattern_set`, `playlist_set_track`, and `transport_set` do the same for
  their targets. Each changed field still gets its own later-tick readback
  receipt, and an optional `expected_before` guard covers any field you set.
- **One plug-in parameter setter.** `plugin_set_parameter` takes a
  `normalized_value`, a `display_value` in the plug-in's own units, or an
  exact `option`, replacing three setters.
- **Fewer overlapping workflows.** Mix plans are gone: apply direct edits
  with `project_apply_edits`, or validate and execute a Production Run.
  Older profile and intent tools that Plugin Atlas and processing plans
  already covered are removed (see the table below).
- **A smaller listing.** Output schemas are now compacted the same way input
  schemas were in V11, and with 50 fewer tools the listing your client loads
  is much smaller.

## Changes that need attention

- **Every tool has a new name.** Clients reload the tool list when they
  reconnect, so the model picks up the new names on its own. Scripts and
  saved prompts that call tools by name need the table below.
- **Merged setters return per-field receipts.** `mixer_set_track`,
  `channel_set`, `pattern_set`, `playlist_set_track`, and `transport_set`
  return one result with a receipt for each field they changed, in a fixed
  order, the same way a batch does. `verified` is true only when every
  requested field verified. Writes are not atomic: by default the call stops
  after the first write that does not verify (`stop_on_unverified`), always
  stops on an unknown outcome, and never replays or rolls back. Every write is
  tied to the session checked before the first one, even when you pass no
  `session_fingerprint`. An `expected_before` field for a value you are not
  setting is refused rather than ignored.
- **Write order is fixed.** `transport_set` stops playback and recording
  first, then changes tempo, time signature, loop mode, metronome, precount,
  and position, then arms recording and starts playback last, so one call can
  move the playhead and press play. `channel_set` writes a channel's name,
  color, and mixer routing after its mix, solo, and pitch, because those three
  change the channel's fingerprint; a `channel_fingerprint` guard applies to
  every write up to and including the first one that changes it.
- **Plug-in tools take `target` only.** The legacy `track_index` plus
  `slot_index` pair is gone; use
  `{"kind": "mixer_effect", "track_index": 3, "slot_index": 0}` or
  `{"kind": "channel_generator", "channel_index": 2}`.
  `plugin_list_loaded` always includes Channel Rack generators, and
  `plugin_list_presets` returns the preset count and current preset with each
  page.
- **Processing and Atlas name value arguments, not setters.** A processing
  action's `setter` and an Atlas control's `preferred_write_value` (formerly
  `preferred_write_tool`) are now `display_value`, `option`, or
  `normalized_value`: the `plugin_set_parameter` argument that writes the
  control. Plans, runs, and reviews saved by V11 load with the old spellings
  translated.
- **`plugin_list_parameters` replaces both parameter readers.** It walks the
  whole plug-in and returns only real controls. The raw page reader and its
  `name_filter` are removed.
- **`mixer_plan_gain_staging` returns operations.** It no longer stores a mix
  plan; pass its `operations` and `session_fingerprint` to
  `project_apply_edits`.
- **Comparison and masking include recommendations.** `audio_compare_files`
  and `audio_analyze_masking` return the recommendation reports that the
  separate `mix_*_recommendations` tools used to return. The masking tool's
  second file argument is now `instrumental_path` (it was `instrument_path`).
- **`run_validate` returns `validation` and `readiness`.** The plan check that
  `postfader_validate_run` returned is under `validation`;
  `include_readiness=true` also fills `readiness` with the setup scorecard
  that `postfader_creation_readiness` returned.
- **`project_get_summary` carries the transport.** Read playback, recording,
  loop mode, position, tempo, and time signature from its `transport` field.
- **`review_get` has views.** `view="export_request"` and
  `view="delivery_manifest"` replace two separate review tools.

| --- | --- |

## Upgrade

The Universal Bridge script did not change, so FL Studio needs nothing new.

1. Close your AI client.
2. Upgrade PostFader: `pip install --upgrade postfader-fl-studio-mcp`, or use
   the platform ZIP or `.mcpb` from the release page.
3. Reconnect your AI client so it reloads the tool list.

Saved Production Runs, Review Sessions, and Sound Selection history from V11
load unchanged.

## Support and limits

Requirements are unchanged: FL Studio 2026 version 26.1.3 build 5336 or newer,
Python 3.10 to 3.14, and Windows or macOS with one virtual MIDI port. The
[V10 feature and platform limitations](v10.0.0.md) still apply. This release
adds no new live FL Studio qualification; its changes are covered by the
hermetic test suite, which runs on Windows and macOS with Python 3.10 and 3.14.
No personal project files, audio, or prompts are included.
