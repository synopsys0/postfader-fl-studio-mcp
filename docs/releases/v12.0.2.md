# PostFader V12.0.2

V12.0.2 fixes processing plans and readiness checks that could report a goal
as covered without a usable action. It retains 85 tools and 8 resources,
starts read-only, and never saves your project automatically.

## What's changed

- **All advertised stock-effect intents resolve.** Fruity Limiter supports
  `control_dynamics` through its ceiling control, Fruity Reeverb 2 supports
  `darken_reverb`, and Fruity Delay 3 supports `add_depth` without changing its
  timing. Reverb darkening requires an observed positive high-cut frequency;
  an unknown or disabled cutoff remains an explicit gap unless you supply
  controls.
- **Low-end tightening requires the complete chain.** `tighten_low_end`
  requires both EQ and compression. A missing component remains visible even
  when the other component can be planned.
- **Readiness follows the actual plan.** Missing controls, wrong targets,
  unsupported intents, conflicting actions, missing authorization, and action
  limits no longer count as covered processing. An optional gap cannot hide
  a required gap in the same category. Compound-goal diagnostics stay complete
  within the documented 128-goal and 256-action bounds.
- **Windows dry-run tests tolerate bounded cold-start delay.** PowerShell runs
  without interactive input, has a 60-second test timeout, and reports captured
  output on timeout. Installer behavior is unchanged.
- **Security and release documentation is more precise.** Source-stamp
  mismatches are advisory. The external review remains deferred for the
  trusted single-user model; automated tests are not an independent audit.
  Git tag signatures, build provenance, and SBOM attestations are separate
  evidence.

## Choose a package

- **Windows or macOS:** use the matching generic ZIP for guided setup with any
  MCP client, or the matching Codex ZIP for Codex setup.
- **Claude Desktop:** install the matching platform setup first, then import
  the `.mcpb` extension. The extension does not install Universal Bridge or
  configure MIDI.
- **Python:** install `postfader-fl-studio-mcp==12.0.2` from PyPI. The wheel and
  source archive are also attached for Python-based installations.

## Upgrade

The Universal Bridge script is unchanged from V12.0.1.

1. Close your AI client.
2. Upgrade with `pip install --upgrade postfader-fl-studio-mcp==12.0.2`, or
   use the matching platform ZIP or `.mcpb` from this release.
3. Reconnect your client and regenerate processing plans from a fresh profile
   before applying changes. Do not reuse an older plan for the corrected
   intents.

Coming from V11? See the [V12.0.0 name table](v12.0.0.md) for the tool renames.

## Support and evidence limits

Requirements remain FL Studio 2026 version 26.1.3 build 5336 or newer, Python
3.10 through 3.14, and Windows or macOS with one virtual MIDI port.
Historical live qualification used macOS 27.0 arm64 with FL Studio Producer
Edition 26.1.3 build 5336 and Windows 11 x64 with Producer Edition 26.1.4
build 5589. This patch adds no new live FL Studio or third-party plug-in
qualification.

The fixes passed 1,145 checks across 63 hardware-free test files, including
33 processing tests and 19 creation-pipeline integration tests. CI covers
Windows and macOS on Python 3.10 and 3.14, native installer dry-runs, clean
package installs, and MCP SDK compatibility. Those checks use synthetic
fixtures and fake FL APIs; they do not establish live audio quality or certify
every plug-in. No user projects, audio, or prompts are included.

## Signed release and artifact verification

Download from the [GitHub release](https://github.com/synopsys0/postfader-fl-studio-mcp/releases/tag/v12.0.2)
or [PyPI](https://pypi.org/project/postfader-fl-studio-mcp/12.0.2/).
This release uses a signed annotated Git tag. Previously published tags stay
unchanged. Verify the tag separately from the workflow's build-provenance and
SBOM attestations; see [supply-chain verification](../supply-chain.md).

Compare each download with `PostFader-v12.0.2-SHA256SUMS.txt`. The manifest
includes the wheel, source archive, MCPB, four setup ZIPs, and
`PostFader-v12.0.2-SBOM.cdx.json`.

On macOS or Linux, place the assets and checksum file in the same directory:

```sh
shasum -a 256 -c PostFader-v12.0.2-SHA256SUMS.txt
```

On Windows, calculate the chosen asset's digest and compare it with its line
in the checksum file:

```powershell
Get-FileHash .\PostFader-v12.0.2-Windows.zip -Algorithm SHA256
```

See [setup](../setup.md), [tool contracts](../tool-contracts.md), and the
[security policy](../../SECURITY.md). Report reproducible problems through
[GitHub Issues](https://github.com/synopsys0/postfader-fl-studio-mcp/issues).
