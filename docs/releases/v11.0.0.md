# PostFader V11.0.0

V11 makes PostFader lighter for your AI client, read-only on every path until
you allow edits, and much easier to understand. It follows V10.0.0 and includes
the tool-description work that was prepared as 10.0.1 but never released.

## What's new

- **A much smaller tool listing.** The tool input schemas that clients hand to
  the model shrank from about 1.3 MB to about 270 KB (79% less), so clients
  that load every tool spend far less of the model's context on PostFader. Production Run plans now
  list operation names, and the new `postfader_describe_operations` tool returns
  the exact fields of any operation on demand. Every call is still validated
  against the full model, and unknown fields are still refused.
- **Plug-in loading needs write mode.** `plugins_load` on macOS now refuses,
  before opening FL Studio's menu, until session write mode is on. It no
  longer turns write mode on by itself, so "starts read-only" holds on every
  path.
- **Bridge refusals reach your AI.** When the bridge refuses a request before
  running it (too large, or not valid JSON), the client now gets that reason
  as an error instead of a dropped connection, and the request is not retried.
  A MIDI request too large to send is refused locally with "nothing was sent".
- **Clearer tool guidance.** Descriptions now explain prerequisites, effects,
  partial outcomes, and when to pick related tools; mix plans and all 23
  batch-operation types have examples checked against the exported schema.
- **New documentation.** A rewritten README, a [docs index](../README.md), an
  [FAQ](../faq.md), a [comparison](../comparison.md) with other FL Studio MCP
  servers, and a [tool reference](../tools.md) generated from the server.

## Changes that need attention

- **135 tools.** `postfader_describe_operations` is new; nothing was removed.
- **Compact plan schemas.** `postfader_validate_run`, `postfader_execute_run`,
  `postfader_creation_readiness`, and `postfader_continue_run` advertise each
  plan operation by name and shared fields only. A client or script that
  checked plans against the old listed schema should fetch exact operation
  schemas from `postfader_describe_operations`. `sound_selection_apply` and
  `processing_apply_plan` advertise the plans they take back as plain objects.
  The server's validation is unchanged.
- **`plugins_load` requires write mode**, as described above.
- **New refusal error.** A request the bridge refuses before reading its id now
  raises `BridgeError` ("refused ... before running it") instead of a link
  failure.
- **The bridge script changed.** Deploy it again after upgrading (see below).

## Fixes

- The bridge's TCP transport, used in development and tests, now sends its
  refusal before closing, and no longer drops a client on a spurious
  "readable" signal.

## Upgrade

Upgrade in this order; mixed versions refuse to connect.

1. Close your AI client and FL Studio.
2. Upgrade PostFader: `pip install --upgrade postfader-fl-studio-mcp`, or use
   the new platform ZIP or `.mcpb` from the release page.
3. Run `postfader setup` to deploy the matching Universal Bridge.
4. Start FL Studio and reload Universal Bridge from *View → Script output*.
5. Reconnect your AI client so it reloads the tool list.

## Support and limits

Requirements are unchanged: FL Studio 2026 version 26.1.3 build 5336 or newer,
Python 3.10 to 3.14, and Windows or macOS with one virtual MIDI port. The
[V10 feature and platform limitations](v10.0.0.md) still apply. This release
adds no new live FL Studio qualification; its changes are covered by the
hermetic test suite, which runs on Windows and macOS with Python 3.10 and 3.14.
No personal project files, audio, or prompts are included.
